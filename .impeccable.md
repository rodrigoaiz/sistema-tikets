## Design Context

### Users
- Single internal user for now (the help desk operator), likely growing to a small team of agents later.
- Used on desktop, in long sessions throughout the day, glanced at frequently while doing other work — not a quick-check-and-leave tool.
- Audience is technically competent but not a "developer tool" audience — this is an administrative/support tool for a public education program (Prepa en Línea SEP, English course on Moodle).

### Brand Personality
Three words: **sobrio, preciso, confiable** (serious/institutional, precise/utilitarian, dependable).
- Serious and institutional — this supports a public education program, not a startup product.
- Utilitarian and efficient — every pixel should help triage tickets faster, no decorative fluff.
- Still has a point of view — not a bland admin template. Reference point: modern product tools (Linear/Height/Vercel dashboard) rather than legacy enterprise helpdesk software (Zendesk/Freshdesk density-for-density's-sake).

### Aesthetic Direction
- **Theme**: Both light and dark, with a toggle. Dark is the primary/default (long screen sessions), light must be equally polished, not an afterthought.
- **Typography**:
  - UI/display font: **Public Sans** (variable, humanist grotesque originally designed for government digital services — thematically apt for an institutional education tool, distinctive weight range, avoids Inter/system-default monoculture).
  - Mono (ticket IDs, timestamps, technical metadata): **JetBrains Mono**.
  - Both self-hosted (no external font CDN calls — this app is self-hosted on a machine with limited/controlled internet egress).
- **Color**: Deep petrol/teal-blue accent (not the typical Linear-purple or AI cyan-purple gradient cliché). Neutrals subtly tinted toward that hue in both themes. Status colors (priority Baja/Media/Alta, ticket state) use clear, distinct semantic colors — this is functional, not decorative.
- **Anti-references**: No glassmorphism, no gradient text, no left-border accent stripes on cards/alerts, no generic rounded-card-with-shadow grids, no purple-to-blue AI gradients.

### Design Principles
1. **Density with clarity** — this is a data-dense triage tool; prioritize scanability (clear type hierarchy, tabular alignment) over whitespace-for-its-own-sake.
2. **Status is legible at a glance** — priority and ticket state must be distinguishable instantly via color + label, never color alone (accessibility).
3. **Calm urgency** — urgent tickets should stand out without the whole UI feeling alarming or "red everywhere."
4. **One accent, used sparingly** — the petrol accent marks primary actions and key emphasis only; it loses meaning if overused.
5. **Self-hosted, not generic** — fonts, icons, and assets are bundled/self-hosted; no reliance on external CDNs for core UI rendering.
